# Water Jug Problem — Notes

## 1. Problem Overview

The Water Jug Problem is a state-space search challenge. Given two jugs of capacities $J_1$ and $J_2$ with no measurement markings, the objective is to measure an exact target volume $T$ in either jug using an infinite water source and three operations: filling, emptying, and pouring.

## 2. Core Python Concepts & Clarifications

### Q1: Why does the stack initialization look like `[(initial_state, [(initial_state, "Initial State")])]`?

This nested structure allows the search to remember both its current location and the entire historical path taken to get there so the final solution steps can be printed.

- **Layer 1 (Single Step):** `(initial_state, "Initial State")`
  - A tuple storing the coordinate `(0, 0)` and the action label `"Initial State"`.
- **Layer 2 (Path / Breadcrumbs):** `[(initial_state, "Initial State")]`
  - A list holding all steps taken so far from the start.
- **Layer 3 (Stack Entry):** `(current_state, path_so_far)`
  - Bundles where the algorithm currently is with the history that produced it.

**Simplified Multi-Line Equivalent:**

```python
initial_state = (0, 0)
initial_path = [(initial_state, "Initial State")]
stack = [(initial_state, initial_path)]
```

### Q2: How does the neighbor expansion loop work?

```python
for next_state, action in condition(current_state, j1, j2):
    if next_state not in visited:
        new_path = path + [(next_state, action)]
        stack.append((next_state, new_path))
```

- `for next_state, action in condition(...)`: Iterates through all valid next moves generated by the state transition rules.
- `if next_state not in visited:`: Prevents infinite cycles by ensuring states already evaluated are skipped.
- `new_path = path + [(next_state, action)]`: Creates a new list appending the current step to the previous history without mutating the original path.
- `stack.append((next_state, new_path))`: Pushes the new state and its corresponding breadcrumb trail onto the top of the stack (LIFO).

## 3. Common Bugs & Pitfalls to Avoid in Lab Practicals

- **Inverted Pour Math:**
  - Incorrect: `pour_to_2 - x` (produces negative volumes when $x > \text{pour}$).
  - Correct: `x - pour_to_2` for remaining water, and `y + pour_to_2` for destination water.
- **Identity vs Membership:**
  - Incorrect: `if current_state is visited:` (`is` checks object memory identity; evaluates to `False`).
  - Correct: `if current_state in visited:` (`in` checks set membership).
- **Indentation of `return None`:**
  - Must be placed outside the `while stack:` loop. If placed inside, the function terminates on the very first iteration.
- **Driver Block Placement:**
  - `if __name__ == "__main__":` must be at column 0 (unindented), not nested inside any function definition.

## 5. Understanding the Result-Printing Logic

### The ATM Machine Analogy

Think of it like an ATM machine. When you go to an ATM:

- **Case 1:** If the machine successfully finds your money → it prints a receipt showing all details.
- **Case 2:** If there is no money → it prints "Sorry, transaction failed."

That is the entire `if / else` structure:

```python
if solution:
    # Machine found the answer -> print the receipt (the steps)
else:
    # Machine found nothing -> print "No solution exists"
```

### Breaking Down the Two Parts Inside

#### 5.1 What does `len(solution) - 1` mean?

Suppose the solution list has 3 items:

1. `(0, 0)` → You started here (you didn't take any move yet!)
2. `(4, 0)` → Move 1
3. `(1, 3)` → Move 2

- How many items are in the list? Total = `3`.
- How many moves did you actually make? Only `2` moves!

That is why:

```
Total moves = len(solution) - 1
```

$(3 - 1 = 2)$

#### 5.2 What do `enumerate` and the format spec `{action:<38}` do?

Take this simple list:

```python
names = ["Apple", "Banana"]

for i, fruit in enumerate(names):
    print(i, fruit)
```

Output:

```
0 Apple
1 Banana
```

`enumerate` just adds a counting number ($0, 1, 2, ...$) automatically!

**What about `{action:<38}`?**

It is just makeup/formatting so the text looks like a neat table in your terminal.

If you don't use it, the arrows look zigzag and messy:

```
Step 0: Start -> (0,0)
Step 1: Fill Jug 1 -> (4,0)
Step 2: Transfer water from Jug 1 to Jug 2 -> (1,3)
```

With `<38`, Python gives every action name exactly 38 spaces of room, so all the arrows `->` line up straight in a line:

```
Step 0: Start                              -> (0,0)
Step 1: Fill Jug 1                         -> (4,0)
Step 2: Transfer water from Jug 1 to Jug 2 -> (1,3)
```
